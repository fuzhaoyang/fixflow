📖 Fixflow 使用文档

一、它是什么

Fixflow 是装在你自己服务器上的 AI 运维助手。用中文描述问题，它会调用命令检查服务器、定位问题，并在你确认后执行修复。所有删除 / 修改 / 安装类操作都必须经你确认。

二、快速开始

  • 运行 fixflow 进入配置向导：选择服务商 → 粘贴 API Key → 选模型 → 选择是否启动面板。
  • 配置完成后自动自检，看到「✅ 全部正常」即成功。
  • 浏览器访问面板：http://127.0.0.1:2222。
  • 随时自检：fixflow doctor。

三、命令行使用（CLI）

运行 fixflow 进入对话，直接发指令，例如：

检查磁盘空间并汇报
防火墙开了哪些端口
帮我清理 /var/log 下 30 天前的日志

内置命令

操作作用
help / ?显示帮助
clear / 清空历史清空当前会话对话
exit / quit退出会话
↑ / ↓ 方向键切换历史输入过的命令
Ctrl+C（任务运行中）中止当前任务（同时中断模型请求）
Ctrl+C（空闲时）退出会话

四、Web 面板

  • 登录：首次访问需注册账号密码，之后登录使用；会话 12 小时有效，可左下角「⚙️」退出登录。
  • 监控：CPU / 内存 / 磁盘 / 网络端口 / Nginx / 防火墙 / Docker / 进程，每 5 秒刷新。
  • AI 对话：直接打字让助手干活，回复逐字显示；修复操作弹「确认执行 / 拒绝」。
  • 设置：左下角「⚙️」→ 模型设置（改 API 地址 / Key / 模型）或重启服务。
  • 清空历史：对话输入框上方「清空历史」按钮。
  • 忘记密码：在服务器上运行 fixflow reset-password 重置。

五、工具与安全

工具用途权限
run_command执行命令检查 / 操作只读自动执行；删除/修改/安装类需确认
read_file读取日志、配置自动执行
apply_fix执行修复命令必须确认
clear_history清空会话历史自动执行

所有写入 / 删除 / 修改操作执行前都会弹确认，输入 y 才执行。已执行的修改无法自动撤销，但操作前都有确认环节。

六、重置模型 / 服务商 / Key

  • 面板：左下角「⚙️ 设置」→ 模型设置，保存即生效。
  • 命令：rm -rf ~/.config/fixflow 后重新运行 fixflow 向导。
  • 直接编辑 ~/.config/fixflow/config.json（baseUrl / model / apiKey）。
  • 每次重新安装后会自动要求重新配置，旧配置备份为 config.json.bak。

七、重启服务

遇到对话异常（如模型返回 400 报错）可一键重启服务解决：左下角「⚙️ 设置」→「重启服务」，或命令行 fixflow restart。重启会清空内存会话（异常上下文随之消失），聊天记录保留在本地。

八、常见问题

现象处理
向导提示"无法连接"服务器访问不了该 API 地址，检查外网 / 防火墙 / 地址
提示"API Key 无效"重新复制粘贴 Key
面板打不开运行 fixflow doctor 检查；未运行就 fixflow web
对话报 LLM API 400多发生在会话上下文异常，点「重启服务」一键修复
监控显示 N/A对应组件没装（如没装 Docker），不影响其他功能

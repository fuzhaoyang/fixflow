# Fixflow 面板国际化（中英）

日期：2026-09-24
状态：需求已对齐

## 背景

面板所有文案硬编码中文。需要支持中英文切换，语言选择**持久化到后端配置文件**（不使用 localStorage）。

## 目标

1. 右上角 `bell-btn`（🔔 告警）**左侧**新增语言切换按钮
2. 面板**全部 UI 文案**中英双语：静态 HTML + JS 动态渲染 + 「使用文档」帮助页
3. 语言选择写入后端 `config.json`（`lang` 字段），刷新保持
4. 服务端动态输出（命令结果 / 采集 detail / 后端错误信息）**保持原文不翻译**

## 需求详情

### 一、后端（`server.js` / `config`）

- `config` 增加 `lang: "zh"` 字段（`loadConfig` 未配置时默认 `zh`）
- `GET /api/config` 返回 `lang`
- `POST /api/config` 保存 `lang`（并入现有 `persistConfig`）
- 前端初始化时 `GET /api/config` 读取 `lang` 应用

### 二、前端 i18n 框架

- 新文件 `src/web/static/i18n.js`：
  ```js
  const I18N = { zh: { "key": "中文" }, en: { "key": "English" } };
  const t = (key) => I18N[curLang][key] ?? key;      // 动态模板用
  function applyLang(lang) { curLang = lang; ... }   // 遍历 [data-i18n] 更新
  ```
- **静态 HTML**：含文案元素加 `data-i18n="key"`（默认 `textContent`，`data-i18n-attr="placeholder|title"` 指定属性）
- **JS 动态模板**：渲染函数里中文文案改为 `t("key")`（按当前语言取值）
- 语言按钮：`conn-wrap` 内 `bell-btn` 左侧 `<button id="lang-toggle">中文 / EN</button>`

### 三、文案键规划

按区域划分键名：`menu.*`、`title.*`、`btn.*`、`modal.*`、`fs.*`、`term.*`、`auth.*`、`help.*` 等。

覆盖范围：
- 菜单/分组/工具栏/状态栏（模型连接提示等）
- 各监控卡片标题、表格头、操作按钮、弹窗标题/文案/按钮/占位符/hint
- 防火墙页、Nginx 页、文件管理器、终端面板、登录/注册、设置弹窗、重启/退出确认
- 「📖 使用文档」帮助页全文

不翻译：命令输出、采集 `detail`、后端返回的错误信息（保持后端原文）。

### 四、切换流程

1. `initPanel()`：`fetch("/api/config")` → `applyLang(config.lang || "zh")`
2. 点击语言按钮：切换语言 → `POST /api/config { lang }` → `applyLang(lang)`
3. 语言切换即时生效（无需刷新）

### 五、测试（node --test）

1. **config lang 持久化**：`GET /api/config` 返回 lang；`POST /api/config { lang: "en" }` 保存到配置文件，重启后仍为 en
2. **i18n 字典完整性**：`i18n.js` 中 zh / en 键集合一致（无缺漏），无缺失值
3. **lang 默认**：无 lang 配置时默认 `zh`

## 不做的事

- 服务端输出/错误信息不翻译
- 不引入第三方 i18n 库（纯手写字典）
- 不做语言自动检测（默认 zh，用户手动切换）

## 风险与降级

| 场景 | 处理 |
|---|---|
| 文案量大 | 分批实施：核心界面（菜单/工具栏/弹窗/监控/文件管理/终端）→ 帮助文档 |
| 漏翻 key | 测试断言 zh/en 键一致，缺失返回原 key 兜底 |
| 后端不可达时切语言 | 切换前本地 `applyLang` 即时生效，POST 失败不阻断（下次刷新恢复） |
